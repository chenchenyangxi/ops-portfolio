Z-AIDOps 智能巡检与告警分析系统

公司已有 Zabbix 监控平台，但日常巡检依赖人工查看页面，监控信息分散，巡检结论不易沉淀。因此基于 Zabbix API、Python、AI 分析和钉钉推送，实现自动化巡检与智能分析流程。系统能够完成监控数据自动采集、AI 摘要生成、结果落盘、钉钉定时推送，并通过日志和运行汇总文件追踪单次执行状态。

项目背景

公司已有 Zabbix 监控平台，但日常巡检依赖人工查看页面，监控信息分散，巡检结论不易沉淀。因此基于 Zabbix API、Python、AI 分析和钉钉推送，实现自动化巡检与智能分析流程。

核心流程

Zabbix API 取数 -> 数据整理与裁剪 -> AI 分析摘要 -> 钉钉推送 -> 本地结果归档 -> 日志与 run_summary 追踪。

Principle

执行原理

整个项目不是单一步骤脚本，而是由数据采集、结构化处理、AI 分析、结果投递和定时调度组成的自动化链路。

数据采集层

Zabbix API
通过接口认证调用版本、主机、监控项和事件相关接口，页面不展示真实地址和凭据
设备筛选逻辑
只对 4 台关键设备执行分析，页面不展示设备名称、内部地址和主机标识
监控窗口
主流程抓最近 24 小时有更新的监控项，早期版本也支持前一天事件摘要分析

分析处理层

Python 数据整理
清洗监控项、统计分类标签，构造成设备级结构化摘要数据
AI 接入
接入 AI 分析接口，按固定提示词输出总体结论、关键风险和处理建议
保护机制
加入 300KB 请求保护和句数限制，避免提交体过大或返回内容过长

结果输出层

文件落盘
每台设备生成结构化数据文件与 AI 摘要文件，公开页面只展示统计结果
运行汇总
统一生成 run_summary.json 记录处理数量、成功数量、失败数量和退出状态
钉钉应用推送
通过企业应用消息把汇总结果发送给指定接收人

持续运行层

Linux 部署
部署到 Linux 服务器目录并创建虚拟环境，公开页面不展示真实部署路径和内部环境信息
定时任务
通过 crontab 定时执行主脚本，并输出 app.log / error.log 便于排查
稳定输出
每次运行生成可追踪结果，并通过 run_id 与运行汇总文件定位单次执行状态

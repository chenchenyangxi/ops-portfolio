四、构建趋势请求节点

节点名称：构建趋势请求

输入变量：

- host：来自“解析主机信息 / host”，Object

- response_body：来自“查询监控项 / body”，String

- window_hours：来自环境变量 window_hours，String，当前值 24

输出变量：

- trend_request_body：String，传给 Zabbix trend.get

- history_request_body：String，传给 Zabbix history.get

- selected_items_text：String，传给“构建历史载荷”

- display_name：String

- role：String

- selected_item_count：Number

- total_items_count：Number

本次修改点：

1. 去掉普通接口 operational status 自动纳入分析，避免大量接口 down 被误报成设备异常。

2. 去掉 Windows service.info、Memory Pages/sec、Page Faults/sec 等噪声指标。

3. 不再把 Used memory / Free memory 这类字节值按 85% 阈值判断，避免内存误报。

4. 保留 CPU 利用率、Memory utilization、磁盘使用率 vfs.fs.pused、swap、agent.ping、ICMP、SNMP 可用性等核心指标。

5. 控制每台设备纳入分析的指标数量，避免 token 过长和钉钉消息过长。

五、构建历史载荷节点

节点名称：构建历史载荷

输入变量：

- selected_items_text：来自“构建趋势请求 / selected_items_text”

- trend_response_body：来自“查询趋势数据 / body”

- history_response_body：来自“查询状态历史 / body”

- display_name：来自“构建趋势请求 / display_name”

- role：来自“构建趋势请求 / role”

输出变量：

- device_payload：Object

- device_payload_text：String

- display_name：String

- role：String

本次修改点：

1. 根据 trend.get 结果生成 period_min、period_avg、period_max。

2. 增加 peak_value、peak_display、peak_time，用于输出峰值和峰值发生时间。

3. 增加 abnormal_hours，表示过去 24 小时中超过阈值的小时数。

4. 增加 recovered_hint，输出“无异常 / 当前仍异常 / 当前已恢复”等状态。

5. 对小数做四舍五入，解决 Dify 输出变量 high precision 报错。

6. 避免使用 Dify 沙箱中可能受限的 min/max，改成自定义列表统计函数。

六、单台设备分析 Prompt 修改

节点名称：构建分析提示词 / 设备分析

本次提示词要求：

- 输出给自己巡检、主管查看、钉钉通知三种场景都能看懂。

- 风险等级只使用三档：正常、关注、严重。

- 单台设备分析格式固定为：状态、概况、异常、建议。

- 对 CPU、内存、磁盘、网络可用性优先引用真实峰值、峰值时间、异常持续小时数、是否恢复。

- 不要把普通接口 down 直接判定为严重，除非它是明确关键链路或导致设备不可达。

- 建议要短，不直接给出自动重启、删除、修改生产配置等高风险动作。

七、生成汇总通知节点

节点名称：生成汇总通知；输入变量：items = 设备迭代 output，title = env.workflow_title；输出变量：summary，类型 String。

GROUP_TITLES = {

"network": "一、网络设备分析",

"server_db_nas": "二、服务器 / 数据库 / NAS 分析",

"rpa": "三、RPA 设备分析",

"other": "其他设备分析",

}

GROUP_ORDER = ["network", "server_db_nas", "rpa", "other"]

# 本节点主要逻辑：

# 1. 从设备迭代 output 中读取每台设备的 analysis、display_name、role、group。

# 2. 按 group 分成网络、服务器/数据库/NAS、RPA 三块。

# 3. 从 analysis 中识别状态：正常、关注、严重。

# 4. 生成总体概况、三组分析、今日重点关注、需要人工确认事项。

# 5. 人工确认事项只保留真正涉及重启、变更、删除、清理磁盘、扩容等高风险动作。

def _need_manual_confirm(analysis, status):

text = str(analysis or "")

if status == "严重":

return True

hard_keywords = [

"重启", "停机", "切换", "修改配置", "变更配置", "执行变更", "生产变更",

"删除", "清理磁盘", "扩容", "缩容", "防火墙", "安全组",

"交换机配置", "路由器配置", "网络设备变更", "数据库变更", "数据库修改", "权限变更",

]

for keyword in hard_keywords:

if keyword in text:

return True

return False

# 输出变量：summary，类型 String。

十、下午排错记录

1. 模型节点曾出现 api.siliconflow.cn DNS / 网络连接失败，该问题不是 Zabbix 设备清单问题。

2. 构建历史载荷曾出现 high precision 报错，原因是输出变量小数精度过高，后续通过 round 限制精度。

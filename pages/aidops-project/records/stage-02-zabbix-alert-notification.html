Zabbix 基础告警通知闭环完成

第一阶段：Zabbix 基础告警通知闭环完成

项目：Zabbix 监控告警 + 邮件 + 钉钉单聊通知

整理日期：2026-05-27

一、结论

本阶段已经完成 Zabbix 基础告警通知闭环：Zabbix 触发器产生 Problem 后，可通过 Action 同时发送到 163 邮箱和钉钉企业内部应用机器人单聊。

当前已覆盖核心设备的基础可用性、Agent/SNMP 可用性、磁盘空间、CPU/内存/Swap、RPA Agent 状态，以及 SQL Server 1433 端口可用性。NAS 存储池、RAID、硬盘健康和网络接口精细化告警放到第二阶段处理。

通知用户Admin 用户绑定 Email(HTML) 和钉钉单聊机器人。
Action 名称核心设备告警通知。

验证结果临时测试触发器触发后，邮箱和钉钉均收到告警通知。

四、关键配置步骤

1. 配置核心设备 Action 范围

• 将原先只针对出口路由器的通知动作扩展为“核心设备告警通知”，按主机群组做 OR 匹配。

• 选择主机群组：Databases、Linux servers、Network devices、rpa-windows、Zabbix servers、群晖nas。

• 计算方式实际为 B or C or D or E or F or G，表示属于任意一个核心组即可通知。

• 启用时间为 1-7,00:00-24:00。

5. 新增 SQL Server 1433 端口监控

针对 SQL Server Windows 主机 [SQL_SERVER_IP] 新增简单检查，用于确认 SQL Server 业务端口是否可连接。

监控项名称：SQL Server 1433端口可用性

类型：简单检查

键值：net.tcp.service[tcp,[SQL_SERVER_IP],1433]

返回值：1 表示端口可用；0 表示端口不可用。

触发器：max(/SQL_SERVER_HOST/net.tcp.service[tcp,[SQL_SERVER_IP],1433],#3)=0

说明：连续 3 次检测均为 0 时触发严重告警，避免一次网络抖动造成误报。

图：SQL Server 1433 端口可用性监控项配置。原因：SQL Server 关键业务端口需要单独监控；操作：新增简单检查监控项；结果：开始采集 1433 端口可用性。

图：SQL Server 1433 端口监控项测试返回 1。原因：创建触发器前先确认端口监控项可用；操作：点击测试获取值；结果：返回 1，说明 1433 当前可连接。

图：SQL Server 1433 触发器表达式构造器初始选择。原因：手写表达式曾因主机名不匹配报错；操作：改用表达式构造器；结果：自动引用正确主机和监控项。

图：SQL Server 1433 触发器使用 max() 和 #3。原因：避免一次网络抖动误报；操作：设置最近 3 次最大值等于 0；结果：连续 3 次不可用才触发严重告警。

图：SQL Server 1433 端口不可用触发器创建完成。原因：确认新增端口告警已保存并生效；操作：保存触发器；结果：当前状态正常。

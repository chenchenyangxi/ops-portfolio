Dify 应用更新分析和路由日志应用创建

3.dify应用更新分析和路由日志应用创建

整理时间：2026-05-27 14:38

一、文档目的

本文件用于记录 Dify 应用后续改造计划，作为一步一步修改和验收的操作依据。当前原则是不直接改动原有已跑通应用，而是复制副本后逐步修改、逐步测试。

二、总体结论

现有 Zabbix 监控分析应用继续沿用原工作流方式，由 Dify 通过 Zabbix API 拉取已有设备监控数据。路由器日志分析不混入当前监控应用，后续单独创建一个 Dify 日志分析应用。

三、应用拆分设计

1. Zabbix 监控分析应用：扩展已有设备，并按网络、服务器/数据库/NAS、RPA 三个板块汇总。

2. 路由器日志分析应用：单独创建，第一版聚焦 IKE、IPSec、NTP、certificate、drop、attack、cpcar 等关键事件识别。

四、现有 Zabbix 监控分析应用更新

保留原工作流链路：host.get -> item.get -> trend.get -> history.get -> LLM 分析 -> summary 汇总。

副本建议名称：zabbix_monitor_history_24h_ops_plus

输出结构：一、网络设备分析；二、服务器 / 数据库 / NAS 分析；三、RPA 设备分析；四、今日重点关注；五、需要人工确认的事项。

五、设备清单

网络设备一版

• 核心交换机 / 核心

• 出口路由器 [ROUTER_IP]

• Zabbix 服务器 [ZABBIX_SERVER_IP]

服务器 / 数据库 / NAS 一版

• NAS-A

• NAS-B

• NAS-C

• SQL Server Windows 主机 [SQL_SERVER_IP]

• 业务 MySQL 服务器 [MYSQL_SERVER_IP]

• 业务物理机 [PHYSICAL_SERVER_IP]

• 计算节点 [COMPUTE_NODE_A_IP]

• 计算节点 [COMPUTE_NODE_B_IP]

• 计算节点 [COMPUTE_NODE_C_IP]

RPA 一版

• RPA 调度主机 A [RPA_HOST_IP]

• RPA 调度主机 B [RPA_HOST_IP]

• RPA 临时账号主机 [RPA_HOST_IP]

• RPA 主机 C [RPA_HOST_IP]

六、初始化设备节点改造要求

初始化设备节点需要把原来的 4 台设备扩展为上述清单，并给每台设备增加 display_name、role、group、host_candidates。

group 建议取值：network、server_db_nas、rpa。

host_candidates 同时写中文名、IP、可能的 Zabbix 主机名，避免因为主机名不一致导致 host.get 查不到。

七、Prompt 改造要求

单台设备 Prompt 从“只分析当前状态，不给建议”改为输出：设备状态、主要异常、风险等级、处理建议、是否需要人工确认。

风险等级固定为：正常、关注、严重。涉及重启服务、修改生产配置、删除数据、防火墙/安全组/网络设备变更、数据库变更时，必须明确提示需要人工确认。

八、最终汇总节点改造要求

最终 summary 按 group 分成三块输出，先展示每组重点结论，再展示设备明细。查不到的设备应提示“未找到主机或无数据”，但不能影响其他设备分析。

九、路由器日志分析应用创建

应用建议名称：router_syslog_analysis。

第一版输入：路由器日志原文或日志摘要。第一版输出：总体判断、关键事件统计、典型日志样本、风险等级、建议处理动作、需要人工确认事项。

第一版关键字：IKE_NEGO_FAIL、IPSec tunnel negotiation fails、NTP packet、certificate、failed to decrypt、drop、deny、attack、cpcar、storm、loop、abnormal、flood。

后续增强：自动读取日志、定时日报、钉钉推送、和 Zabbix 监控日报合并。

十、操作顺序

1. 在 Dify 页面复制原应用 zabbix_monitor_history_24h，创建副本 zabbix_monitor_history_24h_ops_plus。

2. 副本不修改先运行一次，确认仍能输出原 4 台设备分析。

3. 先修改初始化设备节点，只加服务器 / 数据库 / NAS 一组，测试 host.get 是否能查到。

4. 再补网络组和 RPA 组。

5. 修改最终汇总节点，按三组输出。

6. 修改单台设备 Prompt，增加风险等级、处理建议、人工确认提示。

7. 单独创建 router_syslog_analysis 路由器日志分析应用。

十一、测试标准

• Word 文档能正常打开，内容包含设备清单、分组、改造步骤、测试标准。

• Dify 副本原样能跑通。

• 新增设备后能正常输出，查不到某台设备时不影响其他设备。

• 最终输出按网络、服务器/数据库/NAS、RPA 三组汇总。

• 路由日志应用第一版能识别 IKE、IPSec、NTP、certificate、drop、attack、cpcar 等日志事件。

十二、边界和注意事项

• 原 Dify 应用保持不动，所有修改都在副本里完成。

• 本文档不记录 token、密码、Webhook、API Key。

• AI 分析只作为辅助判断，不自动重启服务、不修改配置、不删除数据、不关闭告警。
